Captured device output used by the parser tests.

- `boot-launch.log`, `dumpsys-*.txt`, `getprop.txt`, `pm-path.txt`, `am-start.txt`, `adb-devices.txt`, `crash-java.log`: taken from the OVH emulator (Android 16, `sdk_gphone64_x86_64`) on 25 October 2026 while building the harness. `getprop.txt` and `dumpsys-*.txt` are trimmed to the lines the parsers read; the other phone's serial in `adb-devices.txt` is masked.
- `lab-run.log`: the `[Svelte boot]`, `"phase":"checks"`, `W SvelteEngine` and `[Svelte stress]` lines of one lab run on the emulator (`engine-app-lab9/log.txt` of the same day).
- `crash-native.log`, `js-errors.log`: lines from earlier lab runs that crashed (`libc` SIGSEGV) and that threw (`E ReactNativeJS`).
- `dumpsys-meminfo.txt`: `dumpsys meminfo io.rasheed.svelteqa` of the release app after a soak scenario on the emulator (26 October), unchanged.
- `soak-run.log`: the `[Svelte soak]` lines and the lab's completion lines of a 70-second `soak-mix` on the emulator (26 October). The two idle windows (3 samples each, after `gc()`) and the 5-second series in between.
- `crash-js-host.log`: a JavaScript fatal of the release app (the lab's `crash-js` scenario, emulator, 26 October): React Native logs `handleHostException` and destroys the host, the process stays alive, no `FATAL EXCEPTION` follows. The frame offset is replaced by 130 to match the small source map the symbolicate tests build.
- `crash-js.log`: a Java crash carrying a JavaScript stack in `name@1:offset` form, written by hand after `JSStackTrace.format`; one crash of another process follows it. `crash-hermes-frames.log`: Hermes `at name (address at index.android.bundle:1:offset)` frames, written by hand.
- `crash-native-tombstone.log`, `ndk-stack-output.txt`: a tombstone written by hand around two real function addresses of `libsvelteengine.so` (build id in the file), and the output of NDK r27's `ndk-stack -sym` over it with the unstripped library; the repository path in the output is replaced by `/repo/`.
- `uia-*.xml`: `uiautomator dump` of the QA app on the OVH emulator (Android 16, 1080x2400, 420 dpi) on 26 October 2026: `screens-menu` (large header), `screens-header`, `screens-slots`, `screens-tabs` (`/__dev/screens` modes), `login-ar` (the login screen with the app language Arabic), `startup-loading` (platform configuration pending), `menu-large-text` (`/__dev/screens` at font scale 2.0, dark), `dev-lab` (`/__dev`). The first line of each file is the tool's own message; the XML follows. They are frozen: the accessibility tests assert what the checklist finds in these files, not what the engine does today.
- `uia-screens-sheet-full.xml`, `uia-screens-sheet-important.xml`, `uia-screens-modal-full.xml`, `uia-screens-modal-important.xml`: the OVH emulator and the QA app, in the TalkBack session of 27 October 2026, `screens-sheet` ("Two detents" over the menu) and `screens-modal` presented: each pair is `uiautomator dump` (every view: the covered menu, which the engine hides from services, and the sheet's scrim, a clickable view that is not important for accessibility) and `uiautomator dump --compressed` (what a service walks). The accessibility tests pin that the plain dump yields findings no service meets (the scrim unlabeled, a button of the menu before the sheet's title and out of order) and the compressed one none.
- `screencap-startup-loading.png`: `adb exec-out screencap -p` of the startup screen while the platform configuration is pending (1080x2400, RGBA as Android writes it).
- `cmd-*.txt`, `wm-*.txt`, `dumpsys-window-insets.txt`, `dumpsys-activity-config-*.txt`: the device-setting commands the suites read and restore, from the same emulator (the dumpsys files are trimmed to the lines the parsers read).
- `ios-crash-objc-exception.ips`, `ios-crash-asi-only.ips`: crash reports of the QA app pulled from the lab iPhone (iPhone SE 3rd generation, iOS 26.6) with `idevicecrashreport -k` on 27 October 2026: `RasheedSvelteQA-2026-10-27-090359.ips` (pid 2958; an `NSRangeException` in `-[SvelteTabView unmountChildComponentView:index:]`, the report carries `exceptionReason`) and `RasheedSvelteQA-2026-10-26-153204.ips` (pid 2000; the same abort, the report carries only `asi`, "abort() called"). Both are the app aborting while the harness ended it. Trimmed: the header line is unchanged; the body keeps what the parser reads (`pid`, `captureTime`, `procLaunch`, `exception`, `termination`, `asi`, `exceptionReason`, `lastExceptionBacktrace`, `faultingThread`, `usedImages`) and only the faulting thread (index 0) of `threads`.
- `ios-jetsam-event.ips`: `JetsamEvent-2026-10-26-232518.ips` from the same pull, trimmed to the entry of the QA app (listed as the frontmost process, not killed) and the one entry the system killed (`dtfilesandboxd`, `reason` `per-process-limit`).
- `ios-screens-toolbar-{ltr,rtl}.{a11y,uikit}.json`, `ios-screens-toolbar-center-{ltr,rtl}.{a11y,uikit}.json`: the app's own accessibility dump and `uikitState` of the lab's toolbar screens (`/__dev/screens?mode=toolbar` and `toolbar-center`; iPhone SE 3rd generation, iOS 26.6, light) from the iPhone accessibility run `a11y-E74A5608-…-20261027T091918Z` of 27 October 2026 (`capture-ltr/`, `capture-rtl/`, `screens-toolbar--light.*`), unchanged. The last visible list row (y 589–607) overlaps the in-flow toolbar's items (y 596–634): that run's four `order` findings. Frozen: the tests assert the band rule on them.
