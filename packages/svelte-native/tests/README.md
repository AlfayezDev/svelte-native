# Tests of `@alfayez/svelte-native`

The package's tests run under Bun (`bun test`). Most of them mount Svelte components, bundled with esbuild, on a fake Fabric host; some compile Kotlin and C++ for the host, bundle a SvelteKit server, or run Node on the packed package. Each test reads as a sentence of the behaviour it checks, and a comment says why, not what.

## Layout

The root of `tests/` holds directories, `tsconfig.json` (the type check of the harnesses that other tools import, `tsc -p tests/tsconfig.json`) and this file. A test lives in the directory of what it checks, with its fixtures in a `fixtures/` next to it and the helpers of its area in a `support/`; what several areas use is in `support/` at the top.

| Directory | What it checks |
|---|---|
| `renderer/` | The renderer and the Fabric host on the fake binding: nodes, payloads against React Native's, refs, view configs, surfaces and hot updates, `fork()`, the app registry |
| `components/` | The components and the HTML elements the lowering turns into them: accessibility, HTML elements and their flow, lists, insets, the keyboard, text whitespace; the HTML differential test (`html-differential.test.ts`) |
| `animation/` | The animation layer (Reanimated's fakes), layout animations, transitions and keyframes |
| `gestures/` | The gesture host against react-native-gesture-handler's own call sequences (golden vectors), lifecycle, guards, responders, HTML presses |
| `foreign/` | The foreign components (maps, video, image, blur, gradients, Lottie, PDF, Rive, shadow, text, capture, ...), and `foreign/svg/`: the SVG components against react-native-svg's own classes |
| `navigation/` | The route tree, the router, screens, tabs, toolbar, `router.prepare`, restoring the navigation state; the stand-in app's tree |
| `kit/` | SvelteKit on the device: `$app/*`, Metro's resolution of it, the remote functions (against a SvelteKit server of the fixture app), `updated` |
| `web-apis/` | `fetch`, `Blob`, `FormData`, `crypto` and storage, `navigator`, geolocation, `matchMedia`, window size, colour scheme, lazy globals |
| `push/` | Push notifications: on the device, the client against a stand-in of the native module `SveltePush`, the `push` state and its hooks in the library's bundle, and a tapped notification through the real router; for a server, the sender (`/push/server`) against local stand-ins for FCM, Google's token endpoint and APNs (HTTP/2): the tokens, the message mapping, every provider answer, the connection |
| `updates/` | The over-the-air updates client, its launch hook and the protocol |
| `compiler/` | The lowering of the primitives and HTML, class resolution and the Tailwind table, Metro's integration, the transformer's options (runes, async mode), worklets, the file watcher |
| `cli/` | `svelte-native` commands: sync, init, doctor, the Expo headless config, variants, capabilities |
| `package/` | What the package ships: exports, `dist/`, declarations and their type budget, packing, the package run by plain Node, docs, and push's place in the one native module (`push-native.test.ts`: the module lists, Firebase `compileOnly` at the plugin's pin, no manifest entry in svelte-core, one gated registration path, the plugin writing and taking away) |
| `startup/` | What loads at boot, the platform lookups and the lite React Native shim |
| `native-host/` | Kotlin and C++ of the native modules, compiled for the host and run; `native-host/contracts/` reads our own native sources and pins what JavaScript relies on |
| `upstream/` | Pins of third-party code: the text of libraries in `node_modules` and of our patches of them, so an update of one fails here and says what changed |
| `support/` | The shared helpers (below), their own tests, and the fixtures several areas mount |

## Running

In `packages/svelte-native`:

- `pnpm test` runs everything: `bun test --timeout 60000`. The timeout matters: Bun kills the child processes of the test process (fixture servers, esbuild) when a test times out.
- A directory or a file: `bun test --timeout 60000 tests/renderer`, `bun test --timeout 60000 tests/navigation/screens-ios.test.ts`; `-t "<name>"` picks tests by name.
- Async mode: `SVELTE_NATIVE_TEST_ASYNC=1|microtask|frames bun test` compiles every component with Svelte's async mode (`support/async-mode-setup.ts`, preloaded by `bunfig.toml`, says what each value does); any other value is the default run. Tests that cannot hold in that mode skip themselves with `test.skipIf(asyncRun)`.
- The Kotlin and C++ checks need `kotlinc`, `java` and `g++` (and an Android SDK `android.jar` and the `org.json` jar for the updates store): `eval "$(bash apps/qa/qa/ci/host-tools.sh)"` puts the pinned ones in the shell. Without a tool those tests skip; with `CI=1` `native-host/native-tools.test.ts` fails instead.
- `tsc -p tests/tsconfig.json` type-checks the harnesses that are imported outside the tests.

## Support

`bunfig.toml` preloads `support/async-mode-setup.ts` and `support/preload.ts`. The helpers, one line each:

| Helper | What it is |
|---|---|
| `host.ts` | The one fake Fabric host: `createHost()` gives the `nativeFabricUIManager` binding (Fabric's rules: a committed node takes no more children, a ScrollView holds one), the log of calls, the committed roots, the event handler, and `install()`, which returns what `restore()`s every global it set; `FakeNode`, `flatten`, `settle` |
| `fake-host.ts` | `fakeHost(options)`: a host installed before each test of a file (or once, `scope: "file"`) and restored after it |
| `globals.ts` | `snapshotGlobals()`: puts the global object back as it was found |
| `preload.ts` | Restores what a test installed when it ends, and what is left when the run ends (Bun runs a preload's `afterAll` once for the process, not for each file), so no file starts with what the one before it left; clears the fake timers a test set (`timers.ts`) |
| `timers.ts` | Clears the timers a test set while its fake timers were on when it ends: Bun keeps the ones that did not fire, and the bundle each one's callback closes over, for the life of the process |
| `bundle.ts` | The one loader of host tests: a fixture and the library's sources bundled with esbuild against stand-ins for React Native, built once per (entry, platform, options) and run afresh for each `load()` as a function, not imported (Bun keeps an imported module for the life of the process, and every collection after a few hundred of them is slower); `bundle`, `evaluate`, `baseStubs`, `appStubs`, `hostPlugin`, `src()` |
| `router.ts` | `loadRouter`, `loadRouterApp`: the bundles of the router tests, with React Native's router-facing modules stood in for by one table whose answers a test chooses through globals (`__navigationOS`, `__navigationInsets`, `__initialURL`, `__backHandlers`, ...) |
| `app-surface.ts` | `appSurface()`: an app started through the app registry, for the surfaces' life, hot updates and restoring |
| `layout-host.ts` | `attachLayout(host)`: the layout half of a fake host for the animation tests (`getBoundingClientRect`, the shadow node family, Reanimated's props registry laid over every commit) |
| `payload-tap.ts` | A view config that also asks React Native's registry for every payload the host builds and records both |
| `rn-reference.ts` | React Native's own code bundled as the oracle: `loadReference`, `reactNativeConverters`, `importWithReactNative`, `withReactNativeGlobals` |
| `reanimated-stubs.ts` | Reanimated's fakes, recorded on `globalThis.__anim` (`AnimLog`) |
| `svg-library-stubs.ts`, `view-configs-stub.ts` | The stubs for react-native-svg's modules, and view configs that pass every prop through |
| `html-harness.ts` | The harness of the HTML elements tests: `load`, `settle`, `host`, `fake`, `emit`, `flat`, `textOf` |
| `fork-harness.ts` | The harness of the `fork()` tests, with Svelte's async mode on: `loadFork`, `fabric`, `find` |
| `tree.ts`, `tree-app.ts` | Hand-written route trees (`page`, `stackOf`) and the stand-in app's tree (`appTree`), with their page fixtures in `fixtures/` |
| `native-host.ts` | `hostTools`, `cachedBuild`, `kotlinHost`, `cppHost`: compile native code for the host, cached by a digest of its inputs, and run it |
| `host-tools.ts` | Where `kotlinc`, `java`, `g++`, `android.jar` and the `org.json` jar are looked for |
| `project.ts` | `createProject`, `withProject`: a scratch project on disk for Metro, CLI and build tests, always removed |
| `css-project.ts` | `cssProject`, `removeCssProjects`: a project with Tailwind linked in |
| `metro.ts` | Metro's side: `fakeConfig`, `resolveFrom`, `realModule`, `until`, `watchUntouched` |
| `versions.ts` | `libraryVersion`, `peerRange`, `peerVersion`, `patchVersion`: versions read from `package.json` and `patches/` |
| `paths.ts` | `packageRoot`, `repoRoot`, `nodeModules` |
| `random.ts` | `random(seed)`: the deterministic generator of the property tests |
| `async-run.ts`, `async-mode-setup.ts` | Which async-mode run this is, and the preload that makes it |
| `fixtures/` | `hello.svelte`, the route and tree pages, and `stand-in-app/`, an app of this package's own that the navigation and compiler tests build |

Areas have helpers of their own in `<area>/support/` (`foreign/support/harness.ts`, `gestures/support/`, `navigation/support/world.ts`, `kit/support/kit.ts` and `remote-harness.ts`, `web-apis/support/match-media-harness.ts`, `push/support/world.ts`, `updates/support/`, ...); they are built on these.

## Rules

- **No global is left behind.** A fake host is installed with `fakeHost()` or `createHost().install()` and restored by the handle it returns; a test that sets anything else on the global object takes a `snapshotGlobals()`. The preload restores whatever a test installed when the test ends, so a file does not need an `afterAll` for it, and no file starts with what the one before it left. `mock.module` is process-wide in Bun and cannot be taken back: a test that needs one runs a probe in a process of its own (`startup/fixtures/platform-probe.ts`, `web-apis/fixtures/web-apis-probe.ts`); the exceptions are the async-mode preload, `compiler/async-option.test.ts`, which puts the module back, and the four React Native stand-ins of `web-apis/fetch/support/setup.ts`, which the fetch tests and `kit/remote-files.test.ts` load (a package-level suite in a process of its own would end that).
- **Bundle once per file.** Load a fixture through `support/bundle.ts` (or a harness built on it), which keeps the bundle for the run and evaluates it afresh for each `load()`; a bundle with a plugin or a function in its options names itself with `cacheKey`. The Remote client of `kit/` does the same.
- **Versions come from `support/versions.ts`**, read from `package.json` and the patches, so a bump is not an edit of the tests; do not write a version literal.
- **Pins of third-party code are in `upstream/`**; the contracts our JavaScript has with our own native sources are in `native-host/contracts/`; Kotlin and C++ that is compiled and run is in `native-host/`. A test that reads a library's source text and checks nothing of this package's code is a pin.
- **Fixtures sit next to their test** (`fixtures/`), the helpers of an area in its `support/`, and only what several areas use in the top `support/`. A scratch directory comes from `support/project.ts`, which removes it.
- **One fact once.** A duplicate becomes one test (the stronger), the same check over several libraries or platforms a table, and a test that checks nothing is removed; the list below says what was removed or merged and why, so a missing test can be found.
