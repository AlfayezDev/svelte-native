## Cross-group

- navigation/surface-restore.test.ts "iOS: a record that is old, from the future, malformed or no state starts the app on its first screen, and an explicit initialProps.navigation is not overridden" runs six refused records through the whole host for rules that `navigation-restore.test.ts` (group 2) pins as unit tests: "expired" ~ "the window is a day: one that old is still used, one a millisecond older is not"; "the user ended the process" ~ "the system's say: a process the user ended is not restored, one it ended is; a host that does not say is believed"; "restored twice already" ~ "a restore that dies on the way is tried twice and then dropped, so it cannot loop"; "from the future" ~ "a clock that was set back cannot age a record: more than a minute in the future is dropped, a little is skew"; "malformed" ~ "anything that is not a record of a JSON text and a time is malformed"; "not a state" ~ "a JSON text the router cannot read is dropped before it reaches the router". One end-to-end refused case plus the three cases that follow it in the test (props from the host are used as given, Android has the engine module, a host that throws) would keep the wiring covered.
- native-host/screens-ios-records.test.ts (the golden, hostile and grid nativeID corpus of the C++ reader) and `navigation-native.test.ts` (group 2, its corpus built from `navigationProps(...)` for the Kotlin reader) are two hand-kept lists of one wire format for two native decoders; one shared corpus would keep both honest.
- navigation/screens-ios.test.ts mounts `screen-fixture.svelte`, `tabs-fixture.svelte` and `toolbar-fixture.svelte`, which `navigation.test.ts` (group 2) uses too: they stay in tests/ for the final pass to move next to the navigation tests.

- compiler/runes-default.test.ts and cli/runes-environment.test.ts (runes) and `async-option.test.ts` (async, group 2) test the plumbing of two compile options through the same code twice: `RUNES_ENVIRONMENT_VARIABLE` / `runesEnvironment` / `runesDefaultEnabled` and `ASYNC_ENVIRONMENT_VARIABLE` / `asyncEnvironment` / `asyncEnabled`, and `withSvelteNative(config, { runes })` / `{ async }` and `expoEnvironment(..., environment)`: parallel tests ("`runes` is read from the environment..." ~ "the setting"; "withSvelteNative(config, { runes }) hands the setting to the workers it starts..." ~ the same for async; "the Vite plugin's native target runs the export with the setting in the environment..." ~ async-option's `expoEnvironment` assertions). One parametrized test over the two options would cover both.
- cli/runes-environment.test.ts "the transformer's cache key follows the setting, so a changed option never reads a cached component" and `cache-key.test.ts` (group 3) "the cache key holds every module the lowering of a .svelte file is made of": different aspects of the same key (the environment, the modules); no duplicate.

- gestures/responder-native.test.ts (a unit test of `createResponder` with a fake tree) and `gestures/responder.test.ts` (group 1, through the real react-native-gesture-handler module) pin the same three behaviours: "a grant that answers true tells the module with the node's tag, and the release clears it" ~ "a grant that answers true blocks the native responders, and the release gives them back" + "a termination gives them back too"; "a grant that answers nothing, or false, calls nothing" ~ "a grant that does not answer true calls nothing, on grant or on release". The unit file is the stronger (takeover, no hooks): `gestures/responder.test.ts` should keep "never touches RNGH's module" and one end-to-end blocking case.

- web-storage.test.ts `describe("defineLazyGlobal")`, 3 tests, and `fetch/lazy-global.test.ts` `describe("defineLazyGlobal")`, 4 tests, check `src/lazy-global.ts` twice: "makes nothing until the name is read, then once: the accessor is replaced by the value" ~ "a loader that works is called once; a name the scope has already is left alone; an assignment replaces the accessor"; "a name the scope has keeps its value, whatever it is; an assignment replaces the global as for any other, before the first read or after it" ~ the same test's last lines; "when making the value throws the read is undefined (a feature probe works), once warned, the accessor stays and the next read tries again" ~ "a loader that throws: the read is undefined..." + "the loader is tried again on a later read...". Only here: assignment before the first read; only there: warns once on repeated failure, a thrown value that is not an Error. One file should hold the union.
- web-apis/web-apis.test.ts "importing the polyfills defines the three names as accessors and loads neither library, creates no MMKV instance and writes nothing" is the runtime twin of `boot-graph.test.ts` "crypto, localStorage and sessionStorage are accessors the polyfills define, and react-native-quick-crypto, react-native-mmkv and the Nitro runtime are not evaluated at load" (the static import graph). Different method, same rule.
